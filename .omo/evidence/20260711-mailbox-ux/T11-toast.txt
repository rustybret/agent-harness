QA HAPPY PATH
-------------
Decision-matrix + marker-write unit tests above are the QA happy path: they
prove decideRegistrationToast fires exactly once per project per prefs file
(marker-set case returns show:false) and that legacy-senders consumption is a
single-consumer dedup via file deletion. Live toast confirmation (actually
booting the TUI and observing api.ui.toast fire) is deferred to Wave 4's
integration evidence pass per the task spec ("live toast additionally confirmed
later").

QA FAILURE PATH (malformed prefs file)
---------------------------------------
Asserted in the same test run above: the test that feeds decideRegistrationToast
a prefs object where "mailbox" is a string instead of a nested object. The
tolerant walk in decideRegistrationToast treats any non-object segment as
"marker unset" and returns show:true -- matching readTuiPreferencesFileSync's
own tolerant-read contract (malformed root -> {}). The corresponding marker
WRITE path is a no-op-safe call to the existing queueTuiPreferenceUpdate seam
(see tui-preferences.ts:98-111), which already resolves to a silent skip when
the shared preferences file itself is malformed at read-back time (the
"malformed file" branch) -- no new failure mode was introduced; T11 only reuses
this existing write seam, it does not duplicate or reimplement it.

WHY THIS IS ENOUGH
------------------
The full accept-once-per-project decision surface is unit-tested exhaustively
(6 cases for the registration toast decision fn, 4 for the legacy-senders
content decision fn, 7 for the full consume orchestration including both
delete-failure branches). The wiring into tui.ts is a 2-line addition to the
existing poll tick with no new control flow -- tui.test.ts's existing 5 tests
(covering tick scheduling, dispose, error handling) continue to pass unmodified,
proving the wiring did not disturb T9/T10's established poll infrastructure.
Combined with a clean workspace-wide typecheck and zero LSP diagnostics on both
touched files, this is sufficient confidence for a pure-decision +
thin-orchestrator change; the residual risk (a live toast literally rendering
in a running TUI) is explicitly deferred to the plan's Wave 4 integration
evidence pass, as directed by the task spec itself.
