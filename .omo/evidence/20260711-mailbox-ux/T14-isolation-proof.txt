performed from inside a LIVE host opencode session (the agent driving this task runs
under the real, un-sandboxed $HOME=/Users/brethoffman). `ps aux | grep opencode`
shows 17 opencode processes — the host TUI/agent among them — which write the real DB
continuously and independently of the QA.

The decisive proof that the SANDBOX opencode did NOT touch the real store is that the
sandbox created and wrote its OWN separate database:
  sandbox DB : /tmp/t14-qahome.avg8Gy/data/opencode/opencode.db
  size       : 262144 bytes
  sessions   : 2  (exactly the 2 sandbox TUI launches: proj1 + proj3)
The two sandbox TUI sessions landed in the sandbox DB (count=2), NOT in the real DB.
Had isolation failed, the real DB would have gained ~2 QA sessions AND the sandbox DB
would not exist. Instead: sandbox DB exists with the QA's 2 sessions, and the real DB's
+1 delta is attributable to the concurrent host session, not the QA.
