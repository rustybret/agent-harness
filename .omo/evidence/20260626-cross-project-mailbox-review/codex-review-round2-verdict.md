Quote: “`projects` keyed by projectId with `{ access: "allow-all"|"allow-none"|string[], intent_budget: enum ... }`” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:93)). Concrete fix: split into explicit receiver-local fields, e.g. `access: { mode: "allow-all"|"allow-none"|"allowlist", projectIds: string[] }` plus `sender_intent_budgets: Record<projectId, Intent>`, or define `projects[sourceProjectId]` precisely with no nested allowlist ambiguity.

2. location = todo 9 / send tool. Problem: hop bounds are not implementable from the exact input schema. Quote: input only has `targetProjectId`, `intent`, `body`, `priority`, `correlationId`, `supersedes`, but behavior says “`hopCount` incremented + `hopPath` appended” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:169)). There is no trusted parent/reply context to increment from. Concrete fix: add a trusted reply source such as `replyToMessageId`/`parentMessageId`; the tool must look up the processed inbound envelope, inherit `correlationId`, increment `hopCount`, append to `hopPath`, and reject if the parent is missing/mismatched. Fresh sends should define `hopCount=0` and initial `hopPath`.

3. location = todo 5 + todo 8 / pending delivery. Problem: ack semantics conflict. Scope says ack “ONLY after the message is confirmed in session history” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:26)), but todo 5 says a stale pending item “with a successful dispatch is acked” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:131)). Concrete fix: define pending states and reclaim rules: only `history_confirmed` may ack; `dispatch_sent` must first re-check `session.messages()` and either remain pending until TTL or requeue after an explicit unconfirmed-dispatch TTL. Also define that `queued` is not “successful dispatch.”

4. location = todo 14 / opencode-qa isolation. Problem: isolation wording is internally muddy. Quote: “Assert isolation: session DB count unchanged except sandbox-owned state” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:218)). The sandbox DB may legitimately change; the host real DB must not. Concrete fix: require two receipts: host `~/.local/share/opencode/opencode.db` session count/hash unchanged before/after, and sandbox XDG DB path/count showing all test-created state stayed inside the temp sandbox.

5. location = dependency matrix / execution strategy. Problem: wave ordering and parallelization disagree. Wave 4 says it “depend[s] on W3” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:64)), but todo 11 says it can run “parallel with 8,10” ([plan](/Volumes/Topper2TB/Git/agent-harness/.omo/plans/cross-project-agent-mailbox.md:191)). Concrete fix: either make todo 11 truly Wave 4 and remove 8/10 from “parallel with,” or move todo 11 earlier in the matrix with exact prerequisites.
