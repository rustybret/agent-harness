REGISTRY FILE FORMAT
--------------------
~/.omo/project-registry.json
  { "projects": [{ projectId, repoRoot, displayName, lastSeen }] }
projectId is produced ONLY by projectIdForRoot() imported from ../envelope/project-id.ts
(the one shared canonicalizer). realpath() is applied before computing the id.

DISCOVERY ORDER (as specified, EXACT)
-------------------------------------
1. registerProject(repoRoot) — caller passes ctx.directory for the session.
2. Existing registry entries merged by the atomic read-merge-write (upsert by projectId).
3. discoverFromOpenClaw(path) reads reply-session-registry.jsonl line by line; each line
   with { projectPath } is registered as a HINT (does NOT replace existing entries, does
   NOT auto-promote). Invalid JSON lines, lines without projectPath, and unresolvable
   paths (realpath throws) are skipped silently.
NO broad filesystem scan. NO opencode session-DB scan.

CONCURRENCY SAFETY
------------------
registerProject takes the .lock before read-merge-write. atomicWrite writes to
"<path>.tmp-registry-<uuid>.json" then fs.rename (POSIX-atomic). Lock released in
finally even on error. Test "five concurrent registerProject" asserts the JSON parses
and all 5 entries are present (no corruption).

SORT ORDER
----------
listProjects() returns recency-then-alpha: newest lastSeen first; ties broken by
displayName localeCompare ascending. Verified by two tests (distinct timestamps; equal
timestamps -> alpha).
