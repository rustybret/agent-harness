PROBE FINDINGS
--------------
- Every streamed JSON event carries `sessionID` at the top level of the event envelope
  => the session key the cache needs is present on the chat surface.
- Agent-field availability CONFIRMED via code review: plugin-interface.ts `chat.params`
  handler reads `input.agent` (string | {name}), and plugin/chat-message.ts:95-97 already
  does `if (input.agent) updateSessionAgent(input.sessionID, input.agent)` — the same
  `agent` field this resolver's cache will be fed from.
- Sandbox lacks provider auth, so the model call errored (Model not found) before
  producing assistant text. This does NOT affect the resolver: opencode sets `agent` on
  the hook input regardless of model-call success.
- Tab-switch timing was NOT directly instrumented (non-interactive `opencode run` does not
  switch agents mid-session). The last-known window is therefore a documented design
  property, not a measured number. Real-time Tab-switch observation = v2 (not implemented).
